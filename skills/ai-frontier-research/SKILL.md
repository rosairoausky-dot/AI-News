# AI 前沿研究工作台

本文件为 Agent 的需求与验收规范，不代表已有页面已经实现或验证所有功能。用户仅要求整理或审核 Skill 时，只交付文档，不启动采集、安装扩展或修改应用。执行 Agent 与每周发布时，遵循仓库根目录的 `agent.md` 和 `AGENTS.md`。

## 目标与范围

围绕 AI 视频、AI 音乐、世界模型，创建可交互、可持续更新、数据真正保存在本地的 HTML 研究工作台。默认使用中文界面，保留公司、人员、论文的原文名称。

用户强调的核心要求：

- 项目与产品覆盖全面，包括中国和海外的大公司、创业公司、研究团队及开源项目。
- 说明具体公司、项目、产品、算法负责人、核心算法人员，以及公开论文和原始来源链接。
- 在工作台内直接阅读技术更新、产品发布、公司事件等媒介动态；不能只给官网或搜索入口。
- 支持具体文字的字体颜色标注；备注属于具体项目，能够折叠隐藏。
- 备注、标注、收藏、优先级及动态落盘保存，不能只存于页面内存或浏览器缓存。

已有实现时先检查代码、数据和用户记录，增量修改并兼容旧数据；不要把前次交付说明当作功能验证证据。

## 研究覆盖与证据

按“领域 × 中国/海外 × 大公司/创业公司/研究及开源团队 × 产品类型”建立覆盖矩阵，再检索补全。不要将少数头部项目列表称为全面。

产品类型至少考虑：

| 领域 | 检索维度 |
|---|---|
| AI 视频 | 文生视频、图生视频、视频编辑、角色一致性、数字人/表演驱动、音画联合生成、创作平台、模型/API、开源模型 |
| AI 音乐 | 歌曲与人声生成、纯音乐/配乐、可控编辑、分轨/重混、音乐模型/API、创作平台、开源项目；标明音效/语音等相邻业务 |
| 世界模型 | 交互式世界生成、空间/3D 世界、视频预测、潜在状态建模、具身与机器人、自动驾驶模拟；区分研究原型与可用产品 |

优先使用官方产品页、技术报告、论文、代码仓库、团队主页及作者公开资料，再用可靠媒体补充。持续检索遗漏的创业团队和新产品，记录覆盖缺口与最后检索时间。名称相同或公司产品线重叠时去重；同公司多个实质不同产品保留独立关联。

每个项目记录：

- 稳定 ID、公司/机构、项目名称、产品清单、领域与交叉领域、国家/地区、产品阶段。
- 产品用途、输入输出、获取方式、模型/API/开源入口；版本与商用信息注明证据日期。
- 算法负责人、算法核心人员、各自角色、所属团队和任职时间依据。
- 算法或模型要点、论文/技术报告标题、作者、发布日期、原文及代码链接。
- 官方社媒账号、关联来源、研究更新时间、事实核验时间、信息缺口。

人物关系必须区分创始人、管理层、产品负责人、算法负责人、论文作者、历史成员。不得凭 CEO 身份或一篇相关论文认定其为具体项目算法负责人；不能确认时写“未公开/待核验”。人物流动按时间记录，历史贡献不等于现任职位。

展示“公司 → 项目/产品 → 人员角色 → 论文/技术贡献”的可点击关系视图，并能返回项目详情。产品页、公司博客与论文分别标识，不能统称论文。没有检索证据的版本、发布日期和团队关系不得补写成事实。

## 动态信息与持续采集

建立独立的每日媒介动态信息区，直接展示标题、摘要/可获取正文、来源账号、原文链接、发布时间、抓取时间、关联公司/项目与事件类型。发布时间缺失时如实标识，不用抓取时间冒充。

支持 X/Twitter、小红书、微信公众号、官方博客、论文、GitHub、Hugging Face 等来源。为项目维护可编辑账号清单，包括平台、账号 ID/主页、所属项目、官方性依据、采集方式、启停状态、上次成功和下次检查时间。

“全部账号”默认指工作台项目清单中已确认且启用监控的账号，而非全平台账号。展示已覆盖、待确认、无法接入数量。项目动态通过明确账号关联优先归类，关键词仅辅助匹配；允许人工修正，不强行归入不相关项目。

采集方式按实际可用能力选择：

- 公开来源：采用 RSS/Atom、公开 API 或可访问页面，自动轮询并增量归档。
- X：有可用官方 API 权限时优先使用；否则明确浏览器采集的依赖与覆盖范围。
- 小红书：可采用用户正常登录的浏览器，采集有权访问的账号页面与动态。验证码、登录过期和限流需显示为状态并暂停相应来源，不绕过访问限制。
- 公众号：区分公开文章页、可用授权数据源与个人微信订阅列表。不能声称网页登录即可读取全部个人订阅内容。

登录由用户在平台官网完成，不要求在对话中提供密码或 Cookie。平台登录、API 凭证、本地扩展配对是三种不同操作，界面应分别解释。

如使用扩展配对：提供明确按钮位置、复制成功反馈、扩展粘贴位置、连接测试及失败原因；配对码仅授权扩展连接本地服务，不作为平台登录凭证。

持续采集需要后台服务或明确的浏览器运行依赖：支持任务队列、去重、限速、失败退避、断点续采、启动恢复；各来源独立报错。间隔可配置，满足日更，按平台能力提供更短轮询。区分手动采集、定时轮询和实时推送，不能用滚动动画表示实时抓取成功。

默认可建议公开源每 15 分钟轮询、页面每 30 秒同步，但这只是可调整配置，不是用户规定值。说明电脑休眠、服务停止、浏览器关闭对不同采集通路的影响。未获授权不购买 API 套餐；安装扩展、设置开机运行等仅在具体任务授权范围内实施。

动态区支持自动滚动、暂停/继续、悬停暂停、按领域/公司/项目/媒介/时间筛选及全文搜索。新增手动动态后立即同步到顶部时间线和对应项目；抓取动态可查看关联依据及原始出处。无结果、抓取失败、登录失效与尚未接入必须分别显示，不放入伪造新闻填充界面。

## 内容标注与项目备注

字体标注作用于用户选中的文字，不以整卡片或整段区域背景着色替代。支持项目、产品、人员、算法、论文及媒介等正文内容。选中文字后显示颜色工具；双击词语或既有标注可循环切换颜色，并可清除恢复原色。

默认循环为黄 → 绿 → 蓝 → 红 → 原色。中文选词或跨节点选区需给出可靠操作方式，不得静默扩大为整块标注。以稳定项目 ID、字段 ID、文字锚点/位置保存标注；刷新、切换项目、重启后恢复。内容更新导致锚点失效时提示重新定位，不能把旧标注误套到其他文字。

备注嵌入具体项目的卡片或详情，不做脱离项目的独立笔记模块。支持编辑、自动保存、折叠隐藏和展开；隐藏不删除内容。卡片和详情的备注内容及折叠状态同步。收藏、优先级也按项目保存。

## 本地持久化与交付

以本地 JSON 或 SQLite 等磁盘文件为可靠数据源；浏览器缓存仅作临时恢复。保存个人状态、项目/账号配置、动态归档与必要的采集状态。凭证与普通导出数据分离，不将登录凭证或配对密钥随项目导出。

提供原子写入、自动备份、可见的成功/失败提示和并发修改保护。实现重新打开恢复、导入导出、旧格式迁移，避免静默覆盖用户数据。HTML 文件被移动或页面缓存被清理不应导致磁盘记录丢失。

纯 HTML 无法独立完成后台采集时，交付 HTML + 本地服务 + 启动器，必要时附登录采集扩展。提供最短可操作使用步骤，清楚区分双击 HTML 的离线模式和启动服务后的模式。除非用户要求部署，不迁移到外部服务器。

## 验收与报告

以实际行为验收，不能仅靠语法检查或按钮存在宣称完成：

1. 三领域的国内外产品覆盖矩阵、来源与缺口可查看；人物角色和论文链接抽样核验。
2. 至少一条公开通路获取真实数据，显示来源、正文摘要与真实时间；重抓不重复入库。
3. 社媒采集分别报告各平台的验证结果；只有用真实登录页面采集成功的通路才能标“已验证”。未登录或缺权限时保留为待用户操作，不冒充可用。
4. 对已接入账号验证自动调度、来源报错隔离与恢复；手动当前页采集不能算持续账号监控。
5. 新增项目动态立即出现在时间线；领域、公司及媒介筛选有效，暂停滚动可操作。
6. 选中一小段文字着色，其他文字和背景不变；双击循环与清除有效，重新打开仍能恢复。
7. 备注折叠后编辑区域真正隐藏；再次展开内容保留；卡片与详情同步。
8. 备注、收藏、优先级、颜色在磁盘中真实存在，重启恢复；写入失败不显示成功；备份可恢复。

交付时列出文件入口、启动方式、已验证项、未完成项及需要用户登录或凭证的具体步骤。明确报告轮询频率与持续运行条件，不把目标功能、未验证代码或某个平台的成功推广成全部平台已完成。

## Agent 与每周行业动态

本 Skill 已作为 AI Frontier Research Agent 的需求规范使用；执行流程见仓库根目录 `agent.md` 和 `AGENTS.md`。新增行业动态模块每周检索技术、产品、融资并购、团队人才、政策版权、开源生态和市场合作。默认每周四北京时间 09:00 由 GitHub Actions 运行，发布 `reports/` 和 `site/`。公开报告与本地个人研究数据严格分离。定时配置存在不代表已经在 GitHub 生效，需核查远端工作流运行结果。
