重新发布：建议新建“仓库”，不是单个文件
先审核此版本。以下步骤不需要把密码、Token 或配对码发给我。新仓库名称可用 ai-frontier-agent。


1 · 解压发布包
下载本次 ZIP 并解压。进入包含 README.md、agent.py、.github、site、skills、workbench 的目录。不要把 ZIP 本身上传当作网站。


2 · 创建空仓库
GitHub 右上角 + → New repository。选择账号，填写仓库名，建议 Public 方便免费 Pages；不勾选初始化 README、.gitignore、License，然后 Create repository。请把新的仓库 URL 发给我。


3 · 用 GitHub Desktop 上传，避免反复设备码
安装并登录 GitHub Desktop 官方客户端，File → Clone repository → URL，填入新仓库地址并选择空目录。把发布包内所有内容（包括隐藏的 .github 文件夹）复制到克隆目录。填写提交说明 → Commit to main → Publish branch / Push origin。不要复制旧目录里的 .git 或私人 data 文件。


4 · 配置 GitHub Pages
仓库 Settings → Pages → Build and deployment → Source 选择 GitHub Actions。Settings → Actions → General → Workflow permissions 选择 Read and write permissions 并保存，以允许每周提交报告。


5 · 首次发布 HTML
仓库 Actions → 发布行业动态 HTML → Run workflow → 选择 main。等待所有步骤变绿。Settings → Pages 会显示实际网站 URL，格式一般为 https://账号.github.io/仓库名/ 。第一次首页是本审核入口，含工作台和行业动态。


6 · 验证每周更新
Actions → 每周四行业动态 → Run workflow。确认报告提交出现，随后 Pages 部署成功。日后每周四北京时间 09:00 计划运行（GitHub 可能延迟）；无需本机开机。不要把“上传了 yml”当成已运行成功。


7 · 故障定位
404：看 Pages 是否配置为 Actions、部署是否成功。403：检查 workflow 写权限及分支保护。没有运行入口：检查 .github/workflows 是否在默认分支。全源失败：工作流会失败并保留上次报告。公开页面无法启动 Python：正常，需本地启动器。
